## 1. 전체 시스템 아키텍처

```mermaid
flowchart TD
    U([사용자 채팅]) --> CHAT[chat.py /api/chat/complete<br/>SSE]
    CHAT --> ORCH[build_deep_agent · wiring.py]
    ORCH --> CLS{의도 분류<br/>gpt-4o-mini · LLM}

    CLS -->|ADVISE 일반질문| GATE{KB 게이트<br/>cosine ≥ 0.35}
    GATE -->|근거 있음| KBA[일반지식 인용 답변<br/>grounding 프롬프트]
    GATE -->|근거 없음| CLIO[CLIO 폴백<br/>gpt-4o-mini]

    CLS -->|MANAGE 운영| DA[Deep Agent 루프<br/>orchestrate ⇄ dispatch · MAX_ITER=3]
    CLS -->|GENERATE 생성| GEN[generator 슬롯필링]

    DA --> MGMT[management ReAct 에이전트<br/>graph.py]
    MGMT --> LIVE[live_* 실측도구<br/>Meta 숫자 · 환각금지]
    MGMT --> SKB[search_kb<br/>하이브리드 RRF · CRAG-lite]
    MGMT --> PROP[propose_action<br/>제안만]
    PROP --> HITL{Tier3 위험}
    HITL -->|승인필요| INT[interrupt · 사람 승인]
    INT -.승인후.-> EXE[Executor 단일경로<br/>멱등·감사·Tier 재검증]

    MGMT --> DET[이상감지·에스컬레이션<br/>detection/ · escalation]

    KBA --> CARD[compose_turn → meta.cards<br/>EVIDENCE/RESULT/REVIEW/ACTIONBAR]
    MGMT --> CARD
    CARD --> FE[프론트 카드 렌더<br/>trust boundary · 승인버튼 비활성]

    CHAT --> MEM[(메모리)]
    MEM --> STM[(STM · 체크포인터<br/>AsyncPostgresSaver/Neon)]
    MEM --> LTM[(LTM · management_user_memory<br/>임베딩 시맨틱 회수)]

    SKB --> PV[(pgvector 하이브리드<br/>벡터+GIN tsvector · RRF k=60)]
    PV --> KBT[(management_kb_documents/chunks<br/>trust 라벨)]

    classDef live fill:#d1fae5,stroke:#059669;
    classDef kb fill:#fef3c7,stroke:#d97706;
    classDef act fill:#fee2e2,stroke:#dc2626;
    class LIVE live;
    class SKB,GATE,KBA,PV kb;
    class PROP,HITL,INT,EXE act;
```

**핵심 원칙** — 숫자는 실측도구(`live_*`)에서만, 해석·정책은 KB에서. 운영 변경은 제안만(실행은 사람 승인 Executor 단일경로). 일반질문은 KB 게이트로 근거 있을 때만 인용 답변.

## 5. 데이터 출처 정직성 (발표 기준)

- **환각 임계·이상감지 임계**(cosine 0.35, CPM×1.3, 빈도 3.0)는 **도메인 신호 매핑 + 실측 앵커**다. "실 이상 데이터셋 통계 캘리브"가 아니므로 그렇게 주장하지 않는다.
- **이상감지 목(mock)의 정당성** — 온디맨드 이상 부재·장중 부분데이터 때문에 시나리오 재현은 통제 고장이 본질적으로 필요(이상감지 deep-dive §3·6).
- **개선 델타** — ADVISE 환각은 before/after 둘 다 측정(0.92→1.0). 풀 에이전트 faithfulness는 단일 스냅샷(0.778)만 검증(before 파일 미보존, RAG-지표 §5).
