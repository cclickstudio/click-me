## 2. 최근 작업 — 채팅 통합 (2026-06-27~28)

경구 Deep Agent 베이스에 팀 강점(보은 카드/RAG · 도연 일반KB/시맨틱LTM · 태호 체크포인터)을 흡수해 12갭 자율 구현·검증. **추측이 아니라 데이터가 설계 구멍을 드러내게** 했다.

### 2-1. 구현한 12갭

| 갭 | 내용 | 검증 |
|---|---|---|
| G1 | KB 서브디렉토리 적재 + 시뮬 도메인 오염 차단(화이트리스트) | DB 실측 |
| G4 | **ADVISE KB 게이트** — cosine≥0.35면 인용 답변, 미달이면 CLIO 폴백 + 인용검증 | "ROAS"→KB / "날씨"→CLIO |
| G5 | **source_type 스코핑** — ADVISE 일반지식 ↔ MANAGE 특화 검색 분리 | CP 0.735→0.835 회복 |
| G2 | Deep Agent가 suggested_action 캐리(카드 안 뜨던 버그) | 합성 state |
| G3 | SubagentResult→AskResult 어댑터 | compose_turn→4카드 |
| G6 | 카드 직렬화(meta.cards) + 프론트 렌더러(trust boundary) | **브라우저 시각 검증** |
| G7 | 체크포인터 단일화 + Neon pooler 견고 config | **docker 리눅스 round-trip** |
| M1·M3 | 장기기억 **recall 배선 복구** + anon 격리(누출 차단) | 테스트 |
| M2 | **LLM 추출 게이트** — 선호·결정만 저장·dedup upsert | 선호 저장/잡담 skip |
| M4 | 단기 히스토리 중복 차단(요청별 thread_id) | orchestrator 3회 |
| M6 | 세션 요약 + **임베딩 시맨틱 회수**(Alembic 029) | "목표 뭐였지?"→의미 회수 |

**의도적 설계 이탈 3건:** G6 SSE는 풀 TurnEnvelope 대신 중간경로(meta.cards, 회귀위험↓) · G4 임계값 규칙 정정(C1통과+C2폴백 최대로) · M5(체크포인터 이원화)는 G7에 흡수.

### 2-2. ADVISE 카드 UI (trust boundary)

management가 조치를 제안하면 카드로 렌더: **RESULT**(action_type·tier·rationale) + **REVIEW**(승인필요 판정) + **ACTIONBAR**(버튼). **승인·실행 버튼은 비활성**(executable=False, 실행 API 미연결) — 서버 composer가 trust boundary를 강제(LLM이 정책을 집행하지 않음). EVIDENCE는 기존 citation 칩으로 표시. 브라우저로 렌더 시각 검증 완료.

### 2-3. 메모리 재설계 (write-only → 시맨틱)

- **M3 anon 격리** — recall·remember 둘 다 로그인 사용자만(비로그인 `(global,anon)` 공유 누출 차단, 공식 LangMem namespace 가이드).
- **M1 recall 배선** — 그동안 write-only(회수 미배선)였던 것 복구. `SubagentRequest.memory_context`로 관통.
- **M2 LLM 추출** — 매 턴 "질문 60자" 덤프 폐기. gpt-4o-mini가 선호(semantic)·결정(episodic)만 추출, `dedup_key` upsert로 무한증가 차단.
- **M6 시맨틱 회수** — `embedding Vector(1536)` 컬럼(Alembic 029) + 코사인 top-k. "내 광고 목표가 뭐였지?" → recency(최신=플랫폼) 아닌 **의미적 "트래픽 목표" 회수**.

## 3. 에이전틱 RAG 에이전트 (기반)

```mermaid
flowchart TD
    Q([MANAGE 질문]) --> RE[ReAct 에이전트<br/>LangGraph · 최대 5라운드]
    RE --> LIVE2[live_* 실측<br/>환각금지]
    RE --> SKB2[search_kb<br/>벡터+키워드 RRF]
    SKB2 --> CRAG{CRAG-lite<br/>근거 충분?}
    CRAG -->|충분| ANS([답변+trust+인용])
    CRAG -->|부족| RW[쿼리 재작성·재검색]
    RW --> CRAG
    CRAG -->|여전히 부족| WEB[web_search · advisory]
    RE --> ACT2[propose_action]
    ACT2 --> H2{Tier3}
    H2 -->|승인필요| I2[interrupt]
    LIVE2 --> ANS
    WEB --> ANS
    classDef live fill:#d1fae5,stroke:#059669;
    classDef kb fill:#fef3c7,stroke:#d97706;
    class LIVE2 live;
    class SKB2,WEB kb;
```

### 3-1. 핵심 설계 결정

| 결정 | 선택 | 이유 |
|---|---|---|
| KB 검색 | 하이브리드(벡터+GIN 키워드, RRF 융합) | 벡터가 놓치는 정확 토큰(ROAS·PENDING_REVIEW)을 키워드가 보강. 점수 정규화 불필요 |
| 체크포인터 | AsyncPostgresSaver(Neon), Windows는 MemorySaver 폴백 | 운영(Linux) 영속, 로컬(psycopg-async 비호환) 즉시 폴백 |
| 메모리 저장소 | STM=체크포인터 / LTM=전용 테이블(asyncpg) | LangGraph PostgresStore는 psycopg→Windows 폴백. ORM과 동일 asyncpg로 이식성 |
| 평가 judge | Gemini Flash(환각 중심 채점) | 측정대상(에이전트=OpenAI)과 분리. "환각·거짓·지어낸 수치"만 감점 |
| 리랭커/풀CRAG | 도입 보류(데이터 근거) | recall@3=0.93 → 고칠 노이즈 없음 |

### 3-2. 검색 — 하이브리드 + trust 라벨 + 자기교정(CRAG)

- **하이브리드** — pgvector 코사인(의미) + GIN tsvector(정확 토큰) → **RRF(k=60)** 융합. 임베딩 없는 `keyword_search`도 있어 키 없는 폴백/데모 동작.
- **신뢰도(trust) 라벨** — 모든 청크가 부모 문서의 trust를 달고 인용:
  - **system_backed** — 코드 기준값(CPM 앵커 ₩10,800·CTR 1.71%). **단정 가능.**
  - **advisory** — 외부 참고. "참고이며 직접 측정·관리는 Meta" 단서 필수.
  - **reference** — 출처 있는 구성·통계(세그먼트). 층별 효율 단정 금지.
- **CRAG-lite 자기교정** — 검색 후 `_grade_kb`(LLM)가 "근거가 충분한가" 판정 → 부족하면 쿼리 재작성·재검색 1회 → 여전히 부족하면 `_insufficient` 신호 → `web_search`(Tavily, advisory) 보강 또는 정직히 모른다.
- **source_type 스코핑(2026-06-28 추가)** — ADVISE는 일반지식(general_knowledge+meta_official+benchmark), MANAGE는 특화(meta_official+playbook+benchmark+internal_policy)만 검색 → 상호 오염 차단.

### 3-3. 행동 — 제안 → HITL → 실행

- `propose_action`이 전 ActionType(PAUSE/ACTIVATE/INCREASE_BUDGET/DECREASE_BUDGET/REPLACE_CREATIVE/EXPAND_AUDIENCE/CHANGE_BID_STRATEGY/CREATE_CAMPAIGN) 커버. Tier는 정책 단일원천 `judge_tier`.
- Tier3(돈 늘어남) → `interrupt`로 그래프 멈춤(HITL, 체크포인터 필요).
- 실행 글루: `POST /api/chat/approve` → `finalize_proposal`→`approve`→`Executor.execute`. **모든 write는 Executor 단일경로**(멱등키·감사·Tier 재검증). 어시스턴트는 writer/executor를 직접 호출하지 않음.
- 안전 봉인: `use_mock`이면 MOCK(Meta 미접촉), 아니면 validate_only/live. LIVE는 명시 opt-in일 때만.

### 3-4. 기억 — STM vs LTM

| 종류 | 범위 | 저장 |
|---|---|---|
| 단기(STM) | 한 세션 멀티턴·HITL 재개 | 체크포인터(AsyncPostgresSaver/Neon, Windows MemorySaver 폴백) |
| 장기(LTM) | 세션 넘는 (tenant,user) 선호·결정 | `management_user_memory` + 임베딩 시맨틱 회수 |

원칙: 숫자는 LTM에 안 넣음(실측은 항상 live tool). 정책·선호·결정만.

## 4. 이상감지·에스컬레이션

```mermaid
flowchart TD
    SRC[시간별 스냅샷<br/>실 Meta · 또는 목] --> EXP[기대 곡선<br/>일예산 기반]
    SRC --> OBS[관측 노출]
    EXP --> WIN{이상 구간<br/>기대 대비 미달}
    OBS --> WIN
    WIN --> GUARD{가드레일<br/>DELIVERY_ANOMALY?}
    GUARD -->|아니오| OK([정상])
    GUARD -->|예| DX{결정론 진단<br/>신호 조합 규칙}
    DX -->|CONFIRMED| RES([DiagnosisResult])
    DX -->|INCONCLUSIVE| AGT[진단 에이전트<br/>LLM ReAct]
    AGT --> RES
    classDef real fill:#d1fae5,stroke:#059669;
    class EXP,OBS,WIN,GUARD,DX real;
```

> **source-agnostic** — `run_detection`은 스냅샷만 입력 → 실데이터·목 양쪽 동일 로직.

### 4-1. 판정 기준 (deterministic_dx)

| 이상 유형 | 판정 기준 |
|---|---|
| REVIEW_DELAY | 이상 구간 노출 0 → 이후 회복 & 마지막 공백 < 12시 |
| REVIEW_REJECTED | 이상 구간 전체 노출 0(회복 없음) |
| BID_LOSS | 구간 평균 CPM ≥ CPM 앵커 × 1.3 & 예산 남는데 노출 급감 |
| AUDIENCE_TOO_NARROW | 마지막 빈도 ≥ 3.0(조기 포화) |
| 기타 | INCONCLUSIVE → 진단 에이전트(LLM) |

> CPM×1.3·빈도 3.0은 **실측 앵커 + 도메인 신호 매핑**(통계 캘리브 아님 — 과장 금지).

### 4-2. 에스컬레이션 사다리

| 이상 유형 | 사다리(파괴도 낮은 것 먼저, 마지막은 항상 CREATE_CAMPAIGN) |
|---|---|
| QUALITY_DEGRADED·REVIEW_REJECTED | REPLACE_CREATIVE → CREATE_CAMPAIGN |
| AUDIENCE_TOO_NARROW | EXPAND_AUDIENCE → CHANGE_BID_STRATEGY → CREATE_CAMPAIGN |
| BID_LOSS | CHANGE_BID_STRATEGY → EXPAND_AUDIENCE → CREATE_CAMPAIGN |

> Tier3은 항상 건별 사람 승인. "자동"은 *다음 단계 제안의 자동 생성*만. 회복 판정 = 재탐지로 원래 anomaly 소멸 여부.

### 4-3. 실데이터 vs 목(mock)

| 부분 | 실데이터? | 왜 |
|---|---|---|
| 캠페인 상세(`/campaigns/{id}`) | ✅ 실 Meta hourly → 기대곡선 → 진단 | 연결 계정 실제 게재에 기준 적용 |
| 탐지 로직·기준 | ✅ source-agnostic | 입력만 스냅샷 |
| `/run?fault=` 데모·에스컬레이션 시연 | ❌ 목 | 라이브는 원할 때 안 깨짐(온디맨드 이상 부재) + 장중 부분데이터 오탐 |

```
judge 3/3 일치 20 · 2/3 1 · 약한근거/환각 6
```

**남은 약점 6건** = 대부분 **KB 갭**(거절 대응·CPM 원인·예산 페이스 조치). 모델보다 지식 보강이 다음 레버.

### 5-2. ADVISE 환각 유형별 (개선전→후)

| 유형 | 개선전(CLIO) | 개선후(게이트) |
|---|---|---|
| C1 KB-답변가능 | 1.000 | 1.000 |
| C2 KB-밖 | 1.000 | 1.000 |
| C3 거짓전제 | 1.000 | 1.000 |
| **C4 수치함정** | 0.875 | **1.000** |
| **C5 도메인-밖** | 0.556 | **1.000** |
| **전체** | **0.920** | **1.000** |

> gpt-4o-mini는 이미 C1~C3을 잘함 → 게이트 가치는 **C5(도메인-밖)·C4(수치 날조)**. **grounding 프롬프트**가 fabrication을 막은 것.

### 5-3. Meta 호출 N+1 제거 (86%↓)

캠페인 목록 조회를 계정 단위 `level=campaign` insights로 묶어 캠페인 수와 무관한 상수 호출로 전환.

```
그전  3 + N + 2M = 43 (캠페인 20·활성 10)
지금  상수 ~6                          ── 약 86%↓ · 시간당 1,290→180 · "Meta 요청 한도" 배너 회피
```

**⚠️ 두 환각 지표는 다른 파이프라인** — 풀 에이전트 0.778(live+KB+일반지식) vs ADVISE 게이트 0.92→1.0(KB 제약 단순경로). 혼동 금지.

## 6. eval 기반 품질 개선 (포트폴리오 핵심)

측정 대상=OpenAI gpt-4o-mini, judge=Gemini Flash×3. **measure → try → revert → fix → re-measure** 루프.

1. **검색 베이스라인 → 리랭커 기각** — recall@3=0.93 → 고칠 노이즈 없음을 수치로 확인하고 도입 보류.
2. **Faithfulness 진단** — 베이스라인(엄격 judge)에서 ① judge 과엄격(맞는 일반조언 감점) ② 행동버그(개념질문에 live 덤프·KB 미사용) 식별.
3. **Grounding 게이트 시도 → revert** — 개선 0, 지연만 추가(음성 결과도 결과).
4. **judge 재보정 + 라우팅 수정** — 환각 중심 채점 + 개념질문→search_kb·live 덤프 금지.
5. **약점 추격 → 천장 입증** — 빈도 2.0→5.0 개선했으나 거절·구매의도 회귀(순손해) → revert. **프롬프트 튜닝의 천장**(약점↔정상 트레이드오프)을 측정으로 확정.

> ⚠️ before 시점 결과 파일 미보존 → 개선 델타(before/after)는 풀 에이전트에선 재현 불가. **검증되는 건 단일 스냅샷 0.778**. (ADVISE 게이트는 before/after 둘 다 측정 = 0.92→1.0.)

## 7. 트러블슈팅 3선 (AI 엔지니어 관점 — 발표 하이라이트)

### ① 가짜 지표를 잡았다 — "Faithfulness 1.00"은 측정 오류
- **증상:** 환각 지표 1.00(완벽) → "끝났다" 착각.
- **원인:** judge 모델 `gemini-2.0-flash-lite` **단종(404)** → 판정 다 실패하는데 에러를 **faithful로 오집계**.
- **해결:** judge 교체 + 에러 not_faithful 보수처리(`n_error` 노출).
- **교훈:** **지표 자체를 의심하라.** 측정 인프라가 고장나면 좋은 숫자가 가장 위험하다.

### ② RAG 코퍼스 오염 — 좋은 KB를 더했더니 검색이 나빠졌다
- **증상:** 일반 마케팅 KB(162청크) 추가 → 특화 검색 **CP 0.835→0.735(목표 미달)**.
- **원인:** 일반 청크가 특화 질문에서 정답을 밀어냄(의미적으로 가깝지만 정답 아님).
- **해결:** **source_type 스코핑** — 풀 분리 → **0.835 완전 회복.**
- **교훈:** **코퍼스 확장이 항상 이득은 아니다.** 검색 풀을 용도별로 격리.

### ③ 감 대신 측정 — 리랭커·grounding 게이트를 데이터로 기각
- **해결:** 넣기 전에 측정 → recall@3=0.93 → **리랭커 기각**, grounding 게이트 개선 0 → **revert**.
- **교훈:** **음성 결과도 결과다.** 과투자 방지. 같은 레버 트레이드오프 반복(프롬프트 천장)이면 레버를 바꾼다(KB/모델).

> 보너스: docker 리눅스로 PG 체크포인터 검증(Windows 한계 돌파) · 임베딩 시맨틱 LTM 회수.

## 8. 엔지니어링 교훈 (포트폴리오 포인트)

1. **감 대신 측정** — 리랭커·CRAG·grounding 게이트를 넣기 전에 측정해 2개를 데이터로 기각(과투자 방지).
2. **음성 결과도 결과** — 무효를 측정으로 확인하고 되돌림(복잡도·지연 제거).
3. **측정 정밀도가 먼저** — 소표본·단일 judge 노이즈에 안 속게 n 확대 + judge×3 + 증분 적재.
4. **천장 인지** — 같은 레버로 트레이드오프가 반복되면 멈추고 레버를 바꾼다.
