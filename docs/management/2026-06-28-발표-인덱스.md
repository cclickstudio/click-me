## 2. 트러블슈팅 3선 (AI 엔지니어 관점 — 발표 하이라이트)

### ① 가짜 지표를 잡았다 — "Faithfulness 1.00"은 측정 오류였다
- **증상:** 환각 지표가 1.00(완벽)으로 나옴 → "끝났다" 착각.
- **원인:** judge 모델 `gemini-2.0-flash-lite` **단종(404)** → 모든 판정이 실패하는데 에러 핸들러가 그걸 **faithful로 오집계**.
- **해결:** judge `gemini-2.5-flash-lite` 교체 + 에러를 not_faithful로 보수처리(`n_error` 노출).
- **교훈:** **지표 자체를 의심하라.** 측정 인프라가 고장나면 좋은 숫자가 가장 위험하다.
- 근거: `plans/2026-06-27-채팅-통합-계획.md` 베이스라인 · `evals/rag_eval.py`

### ② RAG 코퍼스 오염 — 좋은 KB를 더했더니 검색이 나빠졌다
- **증상:** 일반 마케팅 KB(162청크) 추가 → management 특화 검색 **Context Precision 0.835 → 0.735(목표 미달)**.
- **원인:** 일반 개념 청크가 특화 질문에서 정답 청크를 밀어냄(의미적으로 가깝지만 정답 아님).
- **해결:** **source_type 스코핑** — ADVISE는 일반지식, MANAGE는 특화만 검색. 풀 분리 → **0.835 완전 회복.**
- **교훈:** **코퍼스 확장이 항상 이득은 아니다.** 검색 풀을 용도별로 격리해야 한다.
- 근거: `plans` G5 · `retriever.py` `MANAGEMENT_SOURCE_TYPES`

### ③ 감 대신 측정 — 리랭커·grounding 게이트를 데이터로 기각
- **증상:** "리랭커·CRAG·grounding 게이트를 넣어야 하나?"를 감으로 판단 중.
- **해결:** 넣기 전에 측정 → 검색 recall@3=0.93(노이즈 없음) → **리랭커 기각**, grounding 게이트는 개선 0 → **revert**.
- **교훈:** **음성 결과도 결과다.** 과투자 방지. 같은 레버로 트레이드오프가 반복되면(프롬프트 천장) 레버를 바꾼다(KB/모델).
- 근거: `specs/2026-06-25-매니지먼트-RAG에이전트-포트폴리오.md` §4·§6

> 추가 트러블슈팅(보너스): docker 리눅스로 PG 체크포인터 검증(Windows 한계 돌파), 임베딩 시맨틱 LTM 회수 — `plans` G7·M6.
