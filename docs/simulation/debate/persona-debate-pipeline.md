# 반응 분석 → 페르소나 토론 파이프라인 설계

> 더미데이터(`backend/domain/simulation/dummy/reaction-dummy.json`)를 분석하고,
> 그 결과로 페르소나 토론을 돌려 광고 개선 리포트를 만드는 전체 설계.

## 한눈에 보는 흐름

```
반응 데이터(19명) → ① 결정론적 집계(숫자 확정) → ② 패널 8명 구성(전문가4 합성 + 일반인4 선발)
                  → ③ 모델 배정(자동) → ④ 3라운드 토론(해석) → 리포트
```

**대원칙**: 숫자는 결정론(집계), 해석은 LLM(토론). 둘을 섞지 않는다.
토론은 항상 실제 반응 데이터에 고정(grounded)되어야 한다 — 새로 지어내면 시뮬레이션이 무의미해진다.

---

## 용어 풀이 (먼저 읽기)

전부 **AISAS 퍼널**(주목 → 흥미 → 검색 → 행동 → 공유) 기준입니다.

| 용어 | 쉬운 뜻 | 이 데이터 예시 |
| --- | --- | --- |
| **완주자** | 광고 보고 끝까지(행동/클릭까지) 간 사람 | P-00006 |
| **피벗** | 딱 중간, 조금만 밀면 넘어올 "스윙 보터" 같은 사람 | P-00011 |
| **거부자** | 광고를 대놓고 싫어한 사람 (`rejected`) | P-00000 |
| **불신자** | 광고를 못 믿는 사람 (`distrust`) | P-00013 |
| **초기 이탈** | 시작(흥미 단계)부터 떨어진 사람 | P-00010 |
| **미온 다수** | "관심은 있는데 굳이 클릭/검색은 안 한" 사람들 — 이 광고에서 제일 많았던 무리(절반 가까이) | P-00011·P-00009 등 |
| **신뢰-행동 갭** | 믿음(trust)은 큰데 살 마음(purchase_intent)은 안 따라온 정도 = `trust − purchase_intent` | 피벗 선정 기준(②) |
| **stance(입장) 점수** | 이 사람이 얼마나 긍정/부정인지 1차원으로 매긴 것 (**② 비판자 선정 전용**) | -7.5(거부) ~ +4.5(완주) |

> **"미온 다수"가 핵심.** 이 광고는 사람들이 *싫어한* 게 아니라 *안 움직인* 게 문제다.
> 그래서 "관심은 있는데 클릭 안 한 무리"를 어떻게 움직이게 하느냐가 캠페인의 숙제.

## ① 분석 결과 도출 (집계)

**LLM 안 씀. 결정론적 집계.** KPI는 SSR 기반이라 토론이 숫자를 만들면 안 된다.

이 데이터(19명) 집계 결과:

### AISAS 퍼널 — 어디서 새는가

```
주목 19 (100%) → 흥미 17 (89%) → 검색 5 (26%) → 행동 5 (26%) → 공유 1 (5%)
                                  ↑ 흥미→검색 구간에서 12명 이탈 = 최대 병목
```

### 4대 KPI

| KPI | 값 |
| --- | --- |
| 클릭 의향률 | 26.3% (신뢰구간 10.5~47.4%, 행동 5/19) |
| 구매의도 | 평균 3.0 — 평균 단언 금지, **분포로 표기** |
| 신뢰도 | 평균 4.05 (높음 — 브랜드 인지도) |
| 거부율 | 5.3% (1/19) |

### 한 줄 해석 (토론 시드)

> 신뢰·흥미는 높은데(89%, 4.05) 클릭 전환이 안 된다(26%). 이탈 절반이 "더 알아볼 이유가 없어서".
> **알리는 데는 성공, 움직이게 하는 데는 실패.**

> **캠페인 목표**: 인스타 광고이므로 구매 전환보다 **클릭 유도**가 핵심.
> KPI 가중을 구매의도가 아니라 클릭 의향률·흥미→검색 이탈에 둔다.

## ② 토론 패널 8명 구성 (도메인 전문가 2 : 마케팅 전문가 2 : 일반인 4)

기존엔 6명 전원을 실제 반응자에서 뽑았지만, 이제 **일반인 4명만 실제 반응자에서 선발**하고
**전문가 4명(도메인 2·마케팅 2)은 합성**한다. 전문가는 데이터에서 "뽑는" 게 아니라 카테고리로 "만든다".

> **왜 일반인을 4명으로?** 일반인의 순수한 소비자 의견은 마케터에게 특히 유용한데, 피벗·비판자 두 극만으론
> 완주자·미온층의 결이 빠진다. 4명이면 [완주/긍정 — 피벗 — 미온 — 비판/부정]으로 소비자 분포를 넓게 커버한다.
> 토론자는 저가 라인(Haiku/mini/Flash)이라 2명 추가의 절대 비용도 작다.

### 핵심 — grounding 두 갈래 (대원칙 정합성)

전문가 4명은 반응 데이터가 없다. 그래서 "토론은 실제 데이터에 grounded" 원칙이 깨지지 않게 **grounding 대상을 둘로 나눈다.**

| 구분 | 인원 | grounded 대상 | 발화 성격 |
| --- | --- | --- | --- |
| 일반인 | 4 | 자기 자신의 **실제 반응** | 1인칭 소비자 목소리 ("나는 안 움직였다") |
| 전문가 | 4 | 조각 8·9의 **분석 결과**(KPI·병목·이탈사유) | 3인칭 진단 ("이 수치는 ~때문") |

> 전문가에겐 분석 결과를 컨텍스트로 강제 주입하고 **"주어진 수치 밖의 사실을 지어내지 말 것"**을 프롬프트 제약으로 박는다.
> 이러면 전문가도 데이터에 grounded된다. **소비자 4 : 전문가 4 균형** — 순수 소비자 목소리와 전문가 진단을 절반씩 섞는다.

### 구성 — 2축 × 2관점 + 일반인 4

```
도메인 전문가 2  (카테고리 슬롯 주입 ← ad_analysis)   광고 카테고리에 맞춰 합성
 ├ 도메인1: 제품·카테고리 인사이트   "{category} 소비자가 이 카테고리에서 뭘 원하나"
 └ 도메인2: 시장·유통·경쟁           "{category} 경쟁 제품 대비 이 광고의 차별점은"
마케팅 전문가 2  (카테고리 무관, 완전 고정)            광고 무관 항상 같은 2관점
 ├ 마케팅1: 퍼포먼스/그로스          전환·CTA·퍼널·클릭 동기 (인스타 클릭 캠페인이라 핵심)
 └ 마케팅2: 브랜드/크리에이티브      메시지·포지셔닝·카피·톤
일반인 4        (실제 반응자에서 선발)                 데이터에 grounded, 분포 범위 커버
 ├ 피벗:   신뢰-행동 갭 최대 미전환자   "조금만 밀면 넘어올 스윙보터"
 ├ 완주자: action 전형(없으면 최대 긍정)  "끝까지 간 긍정 극"
 ├ 비판자: min(stance_score)/거부·불신  "밀어도 안 움직이는 안티 — 개선의 천장"
 └ 미온:   미전환 중 피벗과 결 다른 1명   "관심은 있으나 굳이 안 움직인 다수 결"
```

### 전문가 4명 — 고정 프롬프트 템플릿 (LLM 생성✗)

전문가 페르소나의 **관점(말투·관심사)은 고정 프롬프트**로 두고, 도메인 쪽 `{category}` 슬롯만 변수로 채운다.
LLM으로 매번 생성하면 비결정론·비용·재현성 약화 → **고정이 낫다.**

```python
# 카테고리 출처: ad_analysis 에서 결정론 추출 (자유 텍스트 그대로 슬롯에 끼움)
def detect_category(ad_analysis):
    if ad_analysis is None:
        return "해당 제품"                          # ad_analysis 없으면 generic
    md = (ad_analysis.mismatch_detail or {}).get("category", {})
    return md.get("declared") or ad_analysis.detected_industry or "해당 제품"
    # 예: "과자" / "식품/제품" / "프리미엄 세탁기" — 카테고리가 뭐든 슬롯에 그대로

EXPERTS = [   # 4명 고정. 도메인 2는 {category} 슬롯, 마케팅 2는 무관 고정.
    {"role": "도메인 전문가(제품·카테고리)", "axis": "domain",
     "prompt": "당신은 {category} 분야 제품/카테고리 전문가다. 이 카테고리 소비자가 "
               "무엇을 원하고 무엇에 반응하는지 관점에서 분석 결과를 진단하라."},
    {"role": "도메인 전문가(시장·유통)", "axis": "domain",
     "prompt": "당신은 {category} 분야 시장·유통·경쟁 전문가다. 경쟁 제품 대비 "
               "이 광고의 차별점·약점 관점에서 분석 결과를 진단하라."},
    {"role": "마케팅 전문가(퍼포먼스)", "axis": "marketing",
     "prompt": "당신은 퍼포먼스/그로스 마케터다. 전환·CTA·퍼널·클릭 동기 관점에서 "
               "분석 결과를 진단하라."},
    {"role": "마케팅 전문가(브랜드)", "axis": "marketing",
     "prompt": "당신은 브랜드·크리에이티브 전문가다. 메시지·포지셔닝·카피·톤 관점에서 "
               "분석 결과를 진단하라."},
]
```

> 도메인 전문가만 카테고리에 따라 달라진다(칸쵸→과자 전문가, 세탁기→가전 전문가). 마케팅 2명은 광고와 무관하게 고정.
> 전문가는 stance(입장 점수)가 없다 — 실제 반응이 없으므로. ③ 모델 배정은 역할 기반으로 한다.

### 일반인 4명 — 피벗·완주자·비판자·미온 (결정론, LLM✗)

실제 반응자 전원에서 **분포의 네 결**을 고른다. 배타 배정(이미 뽑힌 사람 제외), 우선순위 피벗 → 비판자 → 완주자 → 미온.

```python
def is_undecided(p):                      # 미전환: 흥미는 있으나 행동 안 함
    return p.interest and not p.action

def pick_pivot(pool):                      # 스윙보터 — 신뢰는 됐는데 행동만 안 함
    cands = [p for p in pool if is_undecided(p)]
    if not cands:
        return None
    # ① 신뢰 절대값 최고 → ② 신뢰-행동 갭 최대 → ③ id 사전순
    tmax = max(p.trust for p in cands)
    top = [p for p in cands if p.trust == tmax]
    gmax = max(p.trust - p.purchase_intent for p in top)
    final = [p for p in top if p.trust - p.purchase_intent == gmax]
    return min(final, key=lambda p: p.persona_id)

def pick_critic(pool, exclude_id):         # 안티 — 밀어도 안 움직이는 "천장"
    cands = [p for p in pool if p.persona_id != exclude_id]
    return min(cands, key=lambda p: (stance_score(p), p.persona_id)) if cands else None

def pick_finisher(pool):                   # 긍정 극 — action 전형, 클릭 0%면 가장 긍정
    fin = [p for p in pool if p.action]
    if fin:
        return pick_representative(fin)
    return min(pool, key=lambda p: (-stance_score(p), p.persona_id)) if pool else None

def pick_second_undecided(pool, pivot):    # 미온 — 미전환 중 피벗과 신뢰 차 최대(다른 결)
    cands = [p for p in pool if is_undecided(p)]
    if not cands or pivot is None:
        return None
    dmax = max(abs(p.trust - pivot.trust) for p in cands)
    top = [p for p in cands if abs(p.trust - pivot.trust) == dmax]
    return pick_representative(top)
```

> **피벗 기준은 캠페인 목표에서 파생된다.** 클릭 전환 캠페인이라 "신뢰-행동 갭"을 쓴다.
> 비판자는 거부·불신이 0명인 좋은 광고에서도 `min(stance_score)`로 **항상 1명 확보** → 칭찬 일색 메아리방 방지.
> 완주자는 클릭 0% 광고(action 0명)에선 "가장 긍정적인 1명"으로 보충 → 긍정 천장을 늘 1명 둔다.

### 엣지 케이스

- **미전환자 0명**(피벗 후보 없음) → 전형(`pick_representative`)으로 보충(`is_fallback=True`). 미온도 미전환 소진 시 전형으로 보충.
- **중복 방지** → 배타 배정. 비판자·완주자·미온은 이미 뽑힌 사람을 후보에서 제외해 항상 서로 다른 사람.
- **표본 부족**(반응자 4명 미만) → 가능한 만큼만 채운다(전문가 4명은 항상 유지).

### 이 데이터의 일반인 선발 결과 (4명) — 규칙을 더미에 돌린 *예시*

| 역할 | 선발 | 규칙이 고른 근거 |
| --- | --- | --- |
| 피벗 ★ | P-00006 | 미전환자 중 신뢰 최고·갭 최대·id 최소 → "믿는데 행동 안 함" |
| 완주자 | P-00010 | `action==true` 전형(중앙값 근접→id순) |
| 비판자 | P-00001 | `min(stance_score)` → 밀어도 안 움직이는 안티 |
| 미온 | P-00009 | 미전환자 중 피벗과 신뢰 차 최대 → "같은 미전환 다른 결" |

> `P-0000x`는 더미에 돌린 *예시 결과*일 뿐 규칙이 아니다. 데이터가 바뀌면 그 안에서 다시 계산된다.

## ③ 페르소나에 AI 모델 배정 (자동)

페르소나 ≠ 모델. **페르소나는 LLM에 넣는 "캐릭터 설정 + 실제 반응 데이터"** 일 뿐이다.
모델 1개로 8명을 다 연기할 수 있다 — system 프롬프트만 다르게 8번 부르면 된다.

### 구성

```
Judge          : Anthropic (Sonnet 4.6)      — 종합·최종 액션 (추론이 핵심, Opus에서 다운)
토론자 8명      : Haiku 3 + GPT 3 + Gemini 2   — 세 엔진 분산, 연기엔 저가 라인으로 충분
```

> 토론자 8명을 세 엔진에 분산(haiku3/gpt3/gemini2). **Judge는 Opus 4.8 → Sonnet 4.6으로 다운그레이드.**

> **왜 Judge를 Sonnet으로?** Judge는 라운드 사이 정리 + 최종 종합으로 **호출이 3~4회뿐**(토론자는 18회)이라
> 여기서 아끼는 비용 효과가 작다. 반면 "여러 발언 종합 → 긴장점 압축 → 개선안 순위"는 다단 추론이 핵심이고
> **Judge가 무너지면 리포트 전체가 무너지는** 가장 비싼 실패 지점이다. Haiku는 이 종합 추론에서 흔들릴 위험 →
> Opus보다 충분히 저렴하면서 종합 추론을 신뢰할 수 있는 **Sonnet이 절충점.**
> (정 더 줄여야 하면 Haiku로 내리되 군집화·순위 일부를 결정론 코드로 떠받치고 LLM은 문장화만 시켜야 버틴다.)

> 왜 토론자는 저가? **호출 많은 곳은 싸게, 적고 중요한 곳은 비싸게.**
> 토론자는 8명 × 라운드 = 많이 부르니 저가, Judge는 3~4번만 부르니 강모델.
> 의견 다양성의 진짜 원천은 모델이 아니라 각 페르소나가 든 **분석 결과·실제 반응 데이터**다.

### 배정 기준 — 역할 기반 라운드로빈 (엔진 ⊥ 역할)

전문가 4명은 실제 반응이 없어 **stance(입장 점수)가 없다** → 기존 "입장순 교차"를 쓸 수 없다.
대신 8명 고정 표시 순서에 엔진을 라운드로빈으로 박아 **한 엔진이 한 역할군(도메인/마케팅/일반)에 쏠리지 않게** 한다.

**절대 금지**: "도메인은 GPT, 마케팅은 Gemini" 식으로 몰기 → 모델 편향과 역할이 뒤섞여
나중에 어떤 의견이 "역할이라서"인지 "모델 말투라서"인지 구분 불가.

```python
JUDGE_ENGINE = "sonnet"   # Sonnet 4.6 (Opus에서 다운 — 호출 적어 비용영향 작고 종합추론 신뢰)

# 8명 고정 표시 순서(slot 1~8) + 엔진 라운드로빈((slot-1)%3) → haiku 3 / gpt 3 / gemini 2.
# 각 엔진이 전문가·일반을 골고루 갖도록 어긋나게 배치(엔진 ⊥ 역할).
PANEL_ORDER  = ["도메인1","도메인2","마케팅1","마케팅2","피벗","완주자","비판자","미온"]
PANEL_ENGINE = ["haiku","gpt","gemini","haiku","gpt","gemini","haiku","gpt"]  # = (slot-1)%3
# 결과: haiku={도메인1,마케팅2,비판자} / gpt={도메인2,피벗,미온} / gemini={마케팅1,완주자}

def assign(panel):
    # slot 1~8 → PANEL_ENGINE[slot-1]. 일반인이 빠져도 전문가 엔진은 slot 고정.
    return {p: PANEL_ENGINE[p.slot - 1] for p in panel}   # Judge는 별도 고정(JUDGE_ENGINE)

def stance_score(p):
    # 일반인(실제 반응자) 전용 — 비판자 선정(②)에 쓴다. 전문가는 반응이 없어 호출 안 함.
    # AISAS 전 단계 매핑(이를수록 부정) + 미정의 값 방어. drop_stage 는 LLM 출력이라
    # attention·action 같은 값도 올 수 있어 .get 으로 KeyError 를 막는다(미정의=중립 1).
    stage_rank = {"attention": 0, "interest": 0, "search": 1, "action": 2, "share": 2, None: 3}
    s = stage_rank.get(p.drop_stage, 1)
    s += (p.purchase_intent - 3) + (p.trust - 3) * 0.5
    if p.rejected:
        s -= 5
    return s
```

- 토론자 8명 = **Haiku 3 / GPT 3 / Gemini 2** (고정 순서 라운드로빈).
- 전부 결정론 → 같은 데이터면 항상 같은 배정 (재현·감사 가능). 사람 손 안 탐.
- 비율·배치 바꾸려면 `PANEL_ENGINE` 리스트만 수정.

### 왜 전 과정이 자동인가

전문가 4명은 카테고리(`ad_analysis`)에서 결정론 합성, 일반인 4명은 `rejected`·`drop_stage`·
`purchase_intent`·`trust` 같은 **이미 있는 필드**로 선발. 모델 배정은 고정 순서.
선발·피벗·비판자·모델 배정 모두 순수 규칙 → **LLM 판단 불필요.** LLM은 이 뒤 토론에서만 쓴다.

## ④ 토론 라운드 (3라운드 고정)

라운드는 고정(비용 예측·재현성·LangGraph 용이). 단 **라운드마다 역할(동사)을 다르게** —
같은 토론을 반복하면 동어반복 + 인위적 수렴만 생긴다.

```
J   토론 주제 제시 (고정 프레임 + 분석결과 초점 주입)
    "신뢰 높은데 클릭 안 됨 — 무엇이 막는가?"
 │
R1 [발산]   병렬·독립    A│B│…│H  ← 서로 안 보고 주제에만 반응 (순서편향 0, 동시호출로 빠름)
 │
J   중간 정리: 의견 군집화 → 핵심 긴장점 1개로 압축
 │
R2 [반박·수렴] 순차·반응형  A→B→…→H   ← R1 전체 + J 질문 보고 동의/반박 (재진술 금지)
 │
J   ★개선 레버 1~2개를 "잠정 액션"으로 제안
 │
R3 [검증]   순차    A→B→…→H   ← "이 액션이면 당신은 클릭하겠나?" (R2 복사 아님, 새 질문)
 │
J   최종 요약: 합의 + 잔여 이견 + 우선순위 액션
```

### 라운드별 역할

| 라운드 | 동사 | 목적 |
| --- | --- | --- |
| R1 | 발산 | 독립 반응 수집 (오염 없는 의견 분포) |
| R2 | 반박 | 상호작용·수렴 (긴장점 규명) |
| R3 | **검증** | Judge 제안 액션을 소비자 패널에 테스트 (개선안 신뢰도) |

### 핵심 포인트

- **R1은 병렬·독립** — 서로 못 보게 해서 휩쓸림(anchoring) 제거 + 동시 호출로 빠름.
- **R2는 반응형** — "재진술 말고 동의/반박하라" → 고정 구조 안에서 상호작용 발생.
- **R3는 검증** — R2 복사가 아니라 "제안 액션이 먹히나"를 소비자에게 물음.
  비판자(밀어도 안 움직이는 안티)가 그 액션에도 안 움직이면 그대로 리포트 신호가 됨.
- **짝수(8명) 걱정 불필요** — 다수결이 아니라 **Judge가 종합·타이브레이크**. 동수 교착 없음.
- **출력 구조화** — 발화를 `{stance, 이유, 제안 레버}` + utterance로 받으면
  Judge가 결정론적으로 집계, 리포트가 그대로 소비.

### LangGraph 매핑

```
topic(J) → [fan-out 병렬: 8명] → reduce(J 중간)
         → [fan-out 반응형: 8명] → reduce(J 액션제안)
         → [fan-out 검증: 8명] → reduce(J 최종)
```

R1·R2·R3 = fan-out(8명), Judge = reduce 노드. 프롬프트는 라운드별 3종 + Judge 3종.

### 유동 라운드 (2~4라운드 자동 조절)

3라운드 고정이 기본이지만, **결론이 일찍 나면 덜 돌고 미심쩍으면 한 라운드 더** 돌리게 자동화한다.
멈춤 판단은 *느낌*이 아니라 *숫자*로 한다 (라운드마다 두 지표를 계산 — 구조화 필드라 결정론).

| 지표 | 뜻 | 계산 |
| --- | --- | --- |
| **churn(변동)** | 지난 라운드 대비 입장 바꾼 사람 수 | `stance` 바뀐 페르소나 수 |
| **dispersion(분산)** | 의견이 얼마나 갈렸나 | 이번 라운드 `stance` 점수의 퍼짐 |

**3갈래 게이트** — "갈렸다 = 무조건 더"가 아니다. 안 바뀌는데 갈려 있으면 더 돌려도 동어반복이라 멈춘다.

```
라운드 N(≥2) 끝
   ├ churn 낮음 + dispersion 낮음  → 정착+합의   → 멈춤 (consensus)   ← 2라운드만에 끝낼 수도
   ├ churn 높음 (아직 움직임)        → 한 라운드 더 (max 안에서)        ← 미심쩍으면 4라운드까지
   └ churn 낮음 + dispersion 높음  → 굳은 이견   → 멈춤 (dissensus)  ← "이견 존재"로 기록
```

```python
MIN_ROUNDS, MAX_ROUNDS = 2, 4   # 최소 2(발산+반박) / 최대 4(비용 상한·종료 보장)
CHURN_TH, DISP_TH = 1, 1.5      # 변동 1명 이하 = 정착 / 분산 1.5 이하 = 합의

def should_continue(round_n, churn, dispersion):
    if round_n < MIN_ROUNDS:
        return True                 # 최소 라운드 전엔 무조건 진행
    if round_n >= MAX_ROUNDS:
        return False                # 상한 도달 → 종료
    if churn <= CHURN_TH:           # 더 이상 안 움직임 → 합의든 이견이든 종료
        return False
    return True                     # 아직 움직임 → 한 라운드 더
```

- LangGraph에선 Judge-reduce 뒤 **조건부 엣지** 하나로 구현 (계속 → fan-out 회귀 / 종료 → 최종 요약).
- 트레이드오프: **재현성이 살짝 떨어진다**(발언이 LLM이라 churn이 매번 다름). 단 min2/max4로 비용·종료는 보장.
- output에 `rounds_run`(실제 라운드 수)·`stop_reason`(consensus/dissensus/max)을 기록해 추적 가능하게 한다.

## ⑤ Output (DB 저장 + 리포트 입력)

토론 단계가 내놓는 최종 결과. **Judge 요약(결론) + 페르소나 발언 전체(증거)** 를 둘 다 담는다.
Judge 요약만 저장하면 근거가 사라지므로, 발언도 같이 저장해 리포트가 "실제 소비자 목소리"를 인용한다.

### 페르소나명 부여 (P-00009 → 사람 이름)

`persona_id`(P-00009)는 DB 내부 번호일 뿐, 리포트엔 못 쓴다. **사람 이름 + 한 줄 프로필**을 붙인다.

- **일반인 4명** — 인구 데이터에서 샘플링되어 성별·나이·성향(OCEAN)을 이미 갖는다 → 그걸로 이름·프로필 생성.
  결정론적으로(persona_id 기반) 부여 → 같은 페르소나는 항상 같은 이름. 예: `P-00009` → `"박준호"`, `"29세 직장인 남성 · 미온형"`.
- **전문가 4명** — 합성이라 인구 데이터가 없다 → 역할에서 이름·프로필을 결정론 부여(역할 키 기반).
  예: 도메인1 → `"김도현"`, `"과자 카테고리 제품기획 전문가"` / 마케팅1 → `"이수민"`, `"퍼포먼스 마케터"`.
- 부여 위치 — 일반인은 페르소나 생성 단계(`tools/persona/factory.py`), 전문가는 합성 단계(조각 10-b). 끝까지 들고 다닌다.

## 최종 구성 요약

```
토론자 8명 + Judge 1명 (총 9개 페르소나)

Judge        : Anthropic Sonnet 4.6         (종합·액션, 호출 적음 / Opus 4.8에서 다운)
토론자 8명    : 도메인 전문가 2 + 마케팅 전문가 2 + 일반인 4
             : Haiku 3 + GPT 3 + Gemini 2    (세 엔진 분산, 역할 기반 라운드로빈)
  └ 전문가 4 : 도메인은 {category} 슬롯·마케팅은 고정 — 합성, 분석결과 grounded
  └ 일반인 4 : 피벗·완주자·비판자·미온 — 실제 반응자에서 선발, 자기 반응 grounded

선발·합성·모델배정 = 100% 자동(결정론) / 토론·해석만 LLM
```
