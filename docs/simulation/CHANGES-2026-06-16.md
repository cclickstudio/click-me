## 1. 프론트 시뮬레이터 실행 화면 신규 (`/simulation/run`)

`/api/simulation/run`(도메인 DDD 라우터, 동기 실행)에 연결되는 화면을 새로 만들었다. 기존 `/simulation` 페이지는 옛 API(`/api/simulate/*`)에 묶여 있어 건드리지 않고 새 라우트로 분리.

| 파일 | 내용 |
| --- | --- |
| `frontend/src/app/simulation/run/page.tsx` (신규) | 입력폼 + 결과 화면. 기존 Toss풍 스타일·`AppLayout`·`KpiCard` 재사용 |
| `frontend/src/lib/api.ts` | `api.simulation.run()` — multipart/form-data 호출 메서드 추가 |
| `frontend/src/lib/types.ts` | `SimRunResult`·`SimPersona`·`SimPersonaReaction`·`SimAggregate`·`SimAdAnalysis`·`SimRunInput` 타입 추가 |

**입력 폼 항목** — 광고 ID, 광고 카피(ad_content), 이미지(파일/URL/없음), 선언 의도(제목·카테고리·목표), 표본 수, allocation(비례/층화), target_mode(AUTO/MANUAL), target_filter(age_min·age_max·gender)

**결과 화면** — 4대 KPI(클릭 의향률+95% CI, 구매의도, 신뢰도, 거부율), 유효표본수·엔진버전·의도불일치 배지, 광고 해석, 루브릭 점수 막대, 페르소나별 반응 목록.

> 참고: `organization_id`·`project_id`는 옵셔널. 시뮬레이션 로직엔 영향 없고 DB 귀속 메타데이터일 뿐. 화면은 선택된 프로젝트가 있으면 자동으로 `project_id`만 실어 보낸다.

## 3. fix — 노출맥락 TV 모순 제거 (메타 전용)

### 문제
`exposure_context`("이 광고를 본 경로")가 일부 페르소나에서 **TV·신문**으로 표시됨. 메타 전용 플랫폼인데 "메타 광고를 TV에서 봤다"는 모순.

### 원인
- 샘플러가 노출후보(`exposure_candidates`)를 **전체 맥락 상위 5개**로 뽑음 → 고령층 셀은 TV가 상위 점령, 소셜피드 맥락이 잘려나감. **16셀 중 9셀**(40~70대, 10대 남)에서 발생.
- 두 반응 어댑터(mock·gemini)가 소셜 후보가 없으면 **아무 맥락이나(TV 포함) 폴백**.

### 수정
| 파일 | 내용 |
| --- | --- |
| `backend/domain/simulation/tools/sampling/persona_sampler.py` | 노출후보를 **소셜피드(SNS·동영상 @ 스마트폰/PC) 맥락만**으로 빌드 (전 셀 reach>0이라 항상 존재) |
| `backend/domain/simulation/adapters/gemini/reaction.py` | 소셜 후보 없어도 **비소셜로 폴백 안 함**, 일반 소셜피드 기본값 |
| `backend/domain/simulation/adapters/mock_engine.py` | 위와 동일하게 비소셜 폴백 차단 |
| `backend/tests/simulation/test_reachability.py` | 옛 버그 동작 검증 테스트를 "비소셜로 폴백 안 함"으로 갱신 |

### 배경 — 도달성 샘플링은 이미 정상
- `proportional + reachability ON`이면 페르소나 집합이 메타 도달 인구로 생성됨(20대 최다, 70+ 거의 없음). 고정 패널 파일이 없어 매번 새로 샘플링 → 도달성 ON 상태로 동작 중.
- `stratified`는 설계상(§3.7) 얇은 층에 floor를 보장하고 도달 쏠림을 `weight`로 보정 → 집합은 평탄, 가중 KPI에 도달 반영. "한국 인구처럼 보이던" 이유.
