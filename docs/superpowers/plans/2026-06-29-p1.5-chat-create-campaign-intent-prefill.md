# P1.5 — 챗 캠페인 생성 인텐트(오케스트레이터 툴) + 폼 prefill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 챗에서 "캠페인 만들어줘"류 발화를 하면 **생성 폼 카드가 자동으로 뜨고**(버튼 없이), 발화에서 말한 값(이름·예산·목표)이 **폼에 미리 채워진다**. P1에서 만든 `ChatCreateCampaignCard`를 그대로 쓴다.

**Architecture:** A안(deepagents-ready) — 인텐트를 `chat.py` 분류기로 손코딩하지 않고, **오케스트레이터(deep_agent)에 `create_campaign` 툴을 추가**한다. LLM이 그 툴을 호출하며 인자(이름·예산·목표)를 뽑고, 툴은 DB를 건드리지 않고 **"생성 폼을 띄워라" 신호(meta.embed + prefill)** 만 낸다. 이 meta는 **기존 SSE 경로로 그대로 흘러가** 프론트가 `ChatCreateCampaignCard`에 prefill을 전달한다. `CampaignForm`은 `initial` prop으로 초기값을 받는다. **`chat.py`·정식 엔드포인트·executor는 미수정.** 이 `create_campaign` 툴이 **deepagents 도입 시 그대로 이식되는 연결점**이다(손코딩 분류기와 달리 폐기 코드 없음).

**Tech Stack:** FastAPI · LangGraph 오케스트레이터(`deep_agent.py`, `llm.bind_tools`) · Next.js/TS · Tailwind. 백엔드 순수 함수(`_state_to_result`)는 pytest로, 프론트는 `pnpm lint`+`pnpm build`+수동.

**상위 설계:** `docs/superpowers/specs/2026-06-29-chat-campaign-actions-reuse-overview-design.md`. **선행:** P1(`2026-06-29-p1-chat-create-campaign-embed.md`) 완료 — `ChatCreateCampaignCard`·embed 렌더·트리거 버튼 존재. **P1 불변** — deepagents 와도 카드/HITL/정식흐름 재사용은 그대로 살아남는다(이 plan은 인텐트만 툴화).

## 참조 — 기존 코드 (구현 중 의존)

- `backend/api/assistant/deep_agent.py` (LangGraph 오케스트레이터):
  - `_SYS_ORCHESTRATOR`(시스템 프롬프트, 도구 선택 유도) · `_TOOL_SPECS`(현재 `ask_management`·`ask_generator`, `llm.bind_tools(_TOOL_SPECS)`).
  - `_OState`(TypedDict) — `messages,orig_messages,sub_results,iteration,thread_id,requires_approval,session_id,context_ad_id,memory_context`.
  - `orchestrate` 노드 — `iteration>=MAX_ITER or requires_approval`면 도구 없이 최종 합성, 아니면 `llm_with_tools.ainvoke`.
  - `dispatch` 노드 — `tool_calls`를 실행. `ask_generator` 분기는 ASK/TRIGGER일 때 `tool_msgs` append 후 **early return**하는 패턴이 있음(이걸 본보기로 `create_campaign` early return).
  - `route` — 마지막 메시지에 `tool_calls` 있으면 `dispatch`, 없으면 `END`.
  - `_state_to_result(state)` — `sub_results`로 `combined_meta`(source,label,engine,citations,used_tools,requires_approval,thread_id,suggested_action,evidence,campaigns,sub_results) 합성 → `SubagentResult`.
  - `run(req)` — 초기 `_OState` 구성 후 `graph.ainvoke`.
- `backend/api/routers/chat.py` `/complete` — orchestrator 결과의 `meta`를 그대로 SSE로 yield(`yield ...{'meta': meta}...`). **이 plan에서 미수정** — `combined_meta`에 embed/prefill이 실리면 자동 전달됨. (단 `meta.get("source")=="management"`일 때만 `compose_turn` 카드 빌드 — `create_campaign`은 source가 `deep-agent`라 안 걸림.)
- 프론트(P1 결과): `chat/page.tsx`의 `SourceMeta`/`Message`(현재 `embed?` 보유), SSE `data.meta` 분기, 렌더 `isCreateCampaignEmbed && <ChatCreateCampaignCard />`. `ChatCreateCampaignCard`(props 없음). `CampaignForm({onSubmit,busy})` 내부 기본값 `name=''`,`objective='traffic'`,`total=1_521`,`totalTouched=false`.

```python
from langchain_core.messages import AIMessage

from api.assistant.deep_agent import _state_to_result


def test_state_to_result_carries_create_prefill():
    state = {
        "messages": [AIMessage(content="새 캠페인 생성 폼을 준비했어요. 값을 확인하고 승인해 주세요.")],

        "thread_id": None,

    result = _state_to_result(state)
    assert result.meta["embed"] == "create_campaign"
    assert result.meta["prefill"] == {"objective": "leads", "total_budget_krw": 50000}


def test_state_to_result_no_prefill_has_no_embed():
    state = {
        "messages": [AIMessage(content="일반 답변")],
        "sub_results": {},
        "requires_approval": False,
        "thread_id": None,
        "create_prefill": None,
    }
    result = _state_to_result(state)
    assert "embed" not in result.meta
```
