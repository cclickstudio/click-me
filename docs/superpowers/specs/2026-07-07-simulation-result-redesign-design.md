# 시뮬레이션 결과 화면 재설계 — 설계 문서

날짜: 2026-07-07 / 브랜치: feat/simulation-yeotaeho
대상: `frontend/src/components/simulator/SimulationResultView.tsx` (및 이를 쓰는 `/simulation/[id]` 라우트, `/simulation` 실행 흐름)

## 배경·문제

현재 결과 화면은 8개 섹션이 세로로 나열돼 스크롤이 5화면 이상이고, 핵심 정보인 페르소나 반응이 좌열 하단에 눌려 작게 보인다. 색상도 목표달성 배너(초록/노랑/빨강 전면 배경)·구매의도(파랑)·거부(빨강)·OCEAN(파랑/빨강)이 동시에 노출돼 산만하다.

## 확정된 방향

- **레이아웃**: 탭 분리형 대시보드 — 히어로(목표달성+KPI) 고정 + 3개 탭.
- **색상**: 블루 모노크롬 — 브랜드 블루(#3182F6) 계열 농도로 통일, 등급·경고는 전면 배경색 대신 텍스트·작은 뱃지로만.

## 화면 구조

### 공통 히어로 (탭 위 항상 고정)

- 제목 행: "시뮬레이터 결과" + run_id·반응 수 메타 + 우측 액션(집행하기 `ExecuteFromSimulation`·headerAction·새 시뮬레이션) — 기존 유지.
- KPI 행(한 줄, 5칸): **목표달성 카드(flex 1.4배)** + 클릭 의향률(CI 병기) + 구매의도 + 신뢰도 + 거부율.
  - 목표달성 카드: 등급 텍스트(높음/보통/낮음, 잉크색 `#191F28`) + 지수/100 + 블루 진행 막대. 전면 배경색 제거. rationale·contributions는 개요 탭 "더보기" 접이식으로 이동(카드 안은 등급+지수+막대만).
  - 거부율 카드: 30% 초과 시 `▲ 주의` 앰버(`#D97706`) 소형 텍스트 — 유일하게 허용되는 비블루 신호.
  - `objective_fit` 없으면 KPI 4장만(기존 폭 배분으로 자연 축소).
- 탭 바: `① 개요` `② 페르소나 반응 (N)` `③ 토론·리포트`. 활성 탭은 블루 밑줄. 탭 상태는 컴포넌트 로컬 state(URL 반영 안 함 — YAGNI).

### 탭 ① 개요

- 2열 그리드 1행: 구매의도 분포(1~5점, 블루 농도 막대) / 거부 사유 분해(**빨강 막대 → 진한 블루 `#1B64DA` 막대**로 교체).
- 2열 그리드 2행: 성향별 반응 OCEAN(격차 양수 `#1B64DA`·음수는 잉크색+`−` 부호, 빨강 제거) / 광고 해석(이미지 썸네일 + 감지 4항목).
- "더보기" 접이식(기본 접힘): 루브릭 차원별 점수 · KOBACO 참고치 · 목표달성 rationale/contributions.
- 하단 고지문(calibration 전 안내) 유지.

### 탭 ② 페르소나 반응

- 상단 컨트롤: 필터 칩(전체 N / 클릭의향 n / 거부 n / QA탈락 n — 기존 showFailed 토글을 필터로 흡수) + 정렬 셀렉트(구매의도순·신뢰도순·기본).
- 본문: **전체 폭 3열 카드 그리드**(lg 3열·md 2열·모바일 1열). 카드 = 인적사항(나이·성별·지역) + AISAS 퍼널(모노스페이스 블루) + 구매·신뢰·감정 + 발화 + 거부/이탈/QA 뱃지.
  - 거부 뱃지: 빨강 배경 제거 → 회색 배경 + 잉크 텍스트(`거부·무관함`). QA탈락 카드는 기존처럼 opacity 60%.
- 카드 클릭 시 상세 펼침(OCEAN·소비가치·미디어행동·사회경제·프로필 서사·가중치) — 기존 expand 로직 재사용. 소비가치 등은 현재 `JSON.stringify` 노출인데 key: value 줄바꿈 나열로 개선.

### 탭 ③ 토론·리포트

- DebatePanel 전체 폭 배치(기존 우열 반쪽 → 전체 폭).
- 그 아래 최종 리포트(`SimulationReportView`) — reportView 없으면 기존 플레이스홀더 문구.
- 토론 완료(onReportView) 시 동작은 기존 로직 그대로.

## 색상 규칙 (블루 모노크롬)

| 용도 | 색 |
| --- | --- |
| 데이터 막대 기본 | `#3182F6` (다크 `#5B9DF9`) |
| 막대 강조/농도 스케일 | `#1B64DA` → `#3182F6` → `#7AB0FF` → `#C9DFFF` |
| 핵심 숫자·등급 텍스트 | 잉크 `#191F28` (다크 `#F2F4F6`) |
| 보조 텍스트 | 기존 `#8B95A1` / `#4E5968` 유지 |
| 경고(거부율↑·표본 부족 ⚠) | 앰버 `#D97706` 텍스트만 (배경 금지) |
| 제거 | 초록/빨강 전면 배경 배너, 빨강 막대, 빨강/초록 등급 텍스트, 노랑 뱃지 배경 |

다크모드는 기존 토큰 체계(`dark:` 변형) 유지, 위 규칙 동일 적용.

## 구현 범위·비범위

**범위**: `SimulationResultView.tsx` 내부 재구성(탭 state·히어로·3개 탭 렌더), 필요 시 페르소나 카드를 별도 파일(`PersonaReactionCard.tsx`)로 분리. `KpiCard` 재사용.
**비범위**: DebatePanel·SimulationReportView 내부 스타일, SegmentComparisonView·IndividualDeepView, 백엔드·API, 데이터 계산 로직(purchaseDist·rejectionDist 등은 그대로 이동만).

## 에러·엣지 케이스

- `agg` 없음(집계 실패): 히어로에 KPI 대신 "집계 없음" 안내 — 기존과 동일하게 조건부 렌더.
- 반응 0건·거부 0건·OCEAN 비교 불가: 각 카드 조건부 숨김(기존 로직 유지).
- 탭 ③에서 토론 완료 → reportView 갱신은 탭 상태와 무관하게 동작(state는 부모 보유 — 기존 구조 유지).
