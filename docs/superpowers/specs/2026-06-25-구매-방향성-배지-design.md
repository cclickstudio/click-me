# 성과 비교 — 구매 축 방향성 배지 추가 (설계)

> 작성일 2026-06-25 · 도메인 management(4-2) · 관련 화면 `manage/compare`

## 배경

성과 비교 탭(`manage/compare`)은 **집행 전(시뮬 예측) ↔ 집행 후(실측 Meta)** 를 나란히 보여주며, 스케일이 다른 두 값을 **직접 환산하지 않고 각자 기준선 통과 여부(방향성)** 로만 비교한다(CLAUDE.md "실측 스케일 환산 금지" 원칙).

현재 카드는 **클릭 축만** 방향 배지가 있다.

- 클릭 축: `클릭의향률(예측)` ⟷ `CTR(실측)` — 각자 기준선 통과 배지(강함 ≥20% / 양호 ≥1%)
- 구매 축: 예측 쪽에 `구매의도 3.7/5` 보조 KPI만 있고, **방향 배지가 없어 비대칭**

마케터·사장님 관점에서 "클릭은 방향 판정이 보이는데 구매는 안 보인다"는 비대칭이 화면 설득력을 떨어뜨린다. 구매 축에도 클릭 축과 **대칭으로** 기준선 통과 배지를 추가한다.

## 핵심 원칙 (변경 없음, 재확인)

- **직접 환산 금지.** `구매의도(1~5 점수)` 와 `CVR(%)` 은 **서로 다른 척도**다. 한쪽을 다른 쪽 단위로 환산하지 않는다. 각자 자기 기준선 통과 여부만 본다.
- 따라서 이번 작업은 **새 % 지표(구매의향률)를 만들지 않는다.** `purchase_intent`(점수)를 그대로 쓰고, 표시 톤은 **"기준선 통과"** (강함/약함·양호/약함)로 간다.
- **종합 판정(verdict)은 클릭 축 단독 유지.** 구매 배지는 *표시 전용*이며 verdict 로직을 바꾸지 않는다(기존의 의도적 결정 보존).
- 절대 환산값(보정 CVR·보정 ROAS)은 calibration anchor가 N(=5)건 이상 쌓인 뒤 별도 단계에서 해금한다(이번 범위 밖, Phase 2).

## 변경 사항

### 백엔드 (management 도메인 내부 — 타 도메인/DB 영향 없음)

파생 계산 필드만 추가하므로 **DB 마이그레이션 불필요**(영속 컬럼 아님).

`backend/domain/management/comparison/schemas.py` — `BeforeAfter`에 필드 2개 추가

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| `purchase_pred_strong` | `bool \| None` | 구매의도 강함(≥3.5/5) 통과. 예측 없으면 None |
| `purchase_act_strong` | `bool \| None` | 실측 CVR 양호(≥2%) 통과. **CVR이 null(전환 추적 전)이면 None** |

`backend/domain/management/comparison/service/before_after_service.py`

- 상수 추가: `CVR_STRONG = 0.02` (구매 축 실측 "양호" 기준선). 클릭 축의 `CTR_STRONG = 0.01` 과 같은 자리. **이 화면의 운영 기준일 뿐 "절대적으로 좋은 CVR"이 아니다**(제품·업종·퍼널에 따라 달라짐) — 주석·문구에 명시.
- `purchase_pred_strong = prediction.purchase_intent >= PURCHASE_HIGH` (`PURCHASE_HIGH = 3.5` 재사용).
- `purchase_act_strong`:
  - `prediction is None` → None (예측 미연결 = 비교쌍 없음 → 판정 보류. **기존 클릭 축 `act_strong`과 동일 규칙** — CVR 값 유무와 무관. 의도적 대칭)
  - `actual.cvr is None` → None (전환 추적 전 → "판정 불가")
  - else → `actual.cvr >= CVR_STRONG`
- verdict·rationale·interpretation 로직은 **그대로**. 두 필드만 채워 반환.

### 프론트 (management 화면)

`frontend/src/lib/api.ts` — `BeforeAfterItem`에 `purchase_pred_strong?: boolean | null`, `purchase_act_strong?: boolean | null` 추가(기존 `pred_strong`/`act_strong` 타입과 동일).

`frontend/src/app/(app)/manage/compare/page.tsx` — 기존 "클릭 방향성" 블록 아래 **"구매 방향성"** 블록을 동일 ⟷ 레이아웃으로 추가.

- 좌: `구매의도 · 예측` `{purchase_intent}/5`, `StrongBadge`(강함 ≥3.5 / 약함 <3.5)
- 우: `CVR · 실측 (실 Meta)` `{cvr}` (null이면 "추적 전"), `StrongBadge`(양호 ≥2% / 약함 <2%, null이면 "판정 불가")
- 블록 캡션에 **"구매의도와 CVR은 척도가 달라 직접 환산이 아니라 각자 기준선 통과로만 비교"** 명시.
- 기존 `StrongBadge` 컴포넌트 재사용(이미 null → "판정 불가" 처리됨).

## 명시적으로 하지 않는 것 (YAGNI)

- 새 `구매의향률(%)` 지표 신설 — 하지 않음(직접 환산 함정).
- verdict에 구매 축 반영 — 하지 않음(클릭 축 단독 유지).
- 보정 CVR·보정 ROAS(절대 환산) — Phase 2, 이번 범위 밖.

## 테스트

- `backend/tests/management/test_before_after_service.py`에 케이스 추가:
  - 구매의도 ≥3.5 & CVR ≥2% → 둘 다 strong=True
  - 구매의도 <3.5 → `purchase_pred_strong=False`
  - CVR null → `purchase_act_strong=None`
  - 예측 None → `purchase_pred_strong=None`
- 기존 verdict 케이스는 **불변**임을 확인(회귀 방지).
