# 채팅 어시스턴트 · 오케스트레이터 스펙 (팀 합의용 초안)

> 목적: 생성·시뮬·관리 기능을 **하나의 채팅**에 연결하고, **모든 LLM 호출·답변을 LangSmith로 추적**하기 위한 공통 스펙을 팀이 함께 확정한다.
> 이 문서는 "정답"이 아니라 **결정 항목 목록**이다. 각 항목의 `결정:` 칸을 회의에서 채운다.

---

## 1. 목표 (Goals)

- **G1. 단일 진입점** — 사용자는 하나의 채팅에서 생성·시뮬·관리·일반조언·불러오기를 한다.
- **G2. 전수 추적** — 모든 LLM 호출/응답이 LangSmith에 남는다(누락 0). 한 대화의 턴들이 스레드로 묶인다.
- **G3. 도메인 독립성** — 각 도메인(생성/시뮬/관리)은 내부 구현(슬롯형/에이전틱 RAG 등)을 자유롭게, 단 **공통 계약**을 지킨다.
- **G4. 비파괴 연결** — 기존 도메인 파이프라인(생성/시뮬/관리 서비스) 코드를 바꾸지 않고 그 위에 오케스트레이터만 얹는다.
- **G5. 예측가능·테스트가능** — 최상위 라우팅은 결정론, 깊은 추론은 도메인 안에서.

### 비목표 (Non-goals, 이번 범위 아님)
- 채팅 대화 자체의 DB 영속화(로컬/무상태 유지) — 합의 시 변경 가능.
- 완전 자율 단일 ReAct(모든 툴을 한 에이전트가) — 추적·제어 난이도로 보류 권장.

---

## 2. 제안 아키텍처 (합의 대상)

```
프론트(단일 채팅, session_id 보유)
  └─ POST /api/assistant/chat
       └─ [공통] Orchestrator  (1턴 = 1 트레이스 루트)
            ├─ classify_intent           (계측 LLM)
            ├─ route → 도메인 서브에이전트 (공통 계약 준수)
            │     ├─ 생성  : 슬롯형(결정론)
            │     ├─ 시뮬  : (팀 결정)
            │     └─ 관리  : 에이전틱 RAG (독립 개발 → 합류)
            ├─ retrieve(불러오기)         (도메인 read)
            └─ advise(일반 조언)          (계측 LLM)
```

- **공통(Common)** = 오케스트레이터 + 라우팅 계약 + 추적/세션 규약 + 핸드오프 이벤트 규약.
- **도메인(Domain)** = 서브에이전트 내부. 슬롯형이든 에이전틱 RAG든 자유.

## 3. 정해야 할 것 (Decision Checklist)

### A. 오케스트레이션
- [ ] **A1. 최상위 라우팅 방식** — (a) 의도분류기 + 도메인 서브에이전트(권장, 예측가능) / (b) 단일 ReAct 전 툴. `결정:`
- [ ] **A2. 의도 카테고리 집합** — generate / simulate / manage / retrieve / advise … 확정. `결정:`
- [ ] **A3. 멀티 의도 처리** — 한 메시지에 두 의도면? (순차 처리 / 되묻기) `결정:`
- [ ] **A4. 엔드포인트·소유** — `/api/assistant/chat` 신설 vs 기존 라우터 확장. 소유 팀. `결정:`

### B. 도메인 서브에이전트 **공통 계약 (가장 중요 — seam)**
- [ ] **B1. 입력 계약** — 오케스트레이터가 서브에이전트에 넘기는 표준(대화 히스토리, 추출 슬롯, session_id, project_id, user). `결정:`
- [ ] **B2. 출력 계약** — 서브에이전트가 돌려주는 표준: `action`(ask|trigger|answer), `message`, `started_event`(job 시작 시). `결정:`
- [ ] **B3. 트리거·핸드오프 이벤트 스키마** — `{event, job_id, stream_url, domain}` 공통 형태. `결정:`
- [ ] **B4. 등록 방식** — 서브에이전트를 오케스트레이터에 어떻게 plug-in(레지스트리/wiring). `결정:`

### C. 상태 / 세션
- [ ] **C1. 대화 상태 보관처** — 프론트 무상태(매 턴 히스토리 재전송) vs 서버 세션(ChatSession). `결정:`
- [ ] **C2. session_id 발급 주체** — 프론트 생성 vs 서버 발급. (추적 스레드 키로 사용) `결정:`
- [ ] **C3. 슬롯 누적 방식** — 매 턴 재추출 vs 누적 저장. `결정:`

### D. LangSmith 추적 (필수 — G2)
- [ ] **D1. 계측 규칙** — "raw SDK(google.generativeai 등) 직접 호출 금지, 계측 LLM(LangChain/`@traceable`)만" 을 팀 규칙으로. `결정:`
- [ ] **D2. 트레이스 루트** — 1턴 = 1 루트 run(`assistant.chat.turn`), 하위 자동 중첩. `결정:`
- [ ] **D3. 스레드 상관키** — 모든 run 메타에 `session_id`(+user_id, project_id). 백그라운드 잡에도 동일 주입. `결정:`
- [ ] **D4. 프로젝트/네이밍** — LANGCHAIN_PROJECT, run 네이밍 규약(`assistant.*`, `generator.*`…). `결정:`
- [ ] **D5. 비용 가시화** — 이미지 모델(gpt-image-1 등)은 토큰 기반이 아니라 per-run 비용 0 → 가격표 설정/usage 수동 부착 여부. `결정:`
- [ ] **D6. 평가(eval)** — LangSmith dataset/LLM-judge 도입 범위. `결정:`

### E. RAG
- [ ] **E1. 코퍼스 소유·분담** — 좋은광고/매체규격/AISAS/KOBACO 등 누가 무엇을. `결정:`
- [ ] **E2. 공용 vs 도메인 전용** — 공통 retrieve 툴 vs 도메인별 RAG(관리=에이전틱 RAG 독립). `결정:`
- [ ] **E3. 벡터 스토어·스키마** — pgvector `documents`/`embeddings` 테이블 단일 합의 + Alembic(공통부, 단독 PR). `결정:`
- [ ] **E4. 임베딩 모델** — 모델/차원(1536) 통일. `결정:`

### F. 핸드오프 / 스트리밍
- [ ] **F1. 잡 진행률 전달** — 도메인 SSE 스트림 재사용(`*_started` → 프론트 구독). `결정:`
- [ ] **F2. 동기 vs 비동기** — 어떤 액션이 즉답(조회), 어떤 게 백그라운드 잡(생성/시뮬). `결정:`

### G. 프론트
- [ ] **G1. UI** — 기존 `/chat` 단일 재사용 + 도메인별 진행률 카드. `결정:`
- [ ] **G2. 결과 표현** — 인라인 진행률/카드 vs 결과 페이지 이동. `결정:`

### H. 협업 / 경계 (DDD)
- [ ] **H1. 서비스 공개 API** — 오케스트레이터가 호출할 각 도메인 진입점 시그니처 합의(내부 import 금지). `결정:`
- [ ] **H2. 공통부 변경 절차** — `api/main.py` append-only, DB 스키마 단독 PR + 사전공지. `결정:`
- [ ] **H3. 통합 시점·테스트** — 독립 개발 → 합류 일정·통합 테스트. `결정:`

## 4. 기능별 방향 가이드 (현 구현 기준)

| 기능 | 현 상황 | 권장 방향 | 비고 |
|---|---|---|---|
| **생성** | LangGraph 5단계 파이프라인(추적됨), 챗 슬롯형 PoC 존재 | **슬롯형(결정론) 서브에이전트** → 파라미터 수집 후 `start_generation` 트리거 | 슬롯 추출 LLM만 **계측 전환** 필요 |
| **시뮬** | `start_simulation` 서비스 + SSE 존재 | 슬롯형 또는 경량 — 파라미터(타깃·표본 등) 수집 후 트리거 | project_id 필요(저장 전제) |
| **관리** | management 도메인(조회/액션 다수) | **에이전틱 RAG(독립 개발)** → 공통 계약으로 합류 | 다단계 질의/액션에 적합 |
| **불러오기** | 생성/시뮬 내역 DB 조회 가능 | 공통 retrieve 툴(도메인 read 요약 + 상세 링크) | 권한(조직/ADMIN) 필터 준수 |
| **일반조언** | CLIO(raw Gemini, **미추적**) | 계측 LLM으로 전환 | D1 규칙 적용 |

> 공통 원칙: **각 도메인 서브에이전트는 내부 자유, 공통 계약(B)·추적(D)·핸드오프(F)만 지킨다.**

## 5. 미해결 / 리스크

- 백그라운드 잡(생성/시뮬)은 비동기 분리라 **완전 중첩 트레이스가 어려움** → `session_id` 스레드로 상관(완전 부모-자식 대신).
- 도메인별 프레임워크 상이(슬롯형 vs 에이전틱 RAG) → **공통 계약(B) 미합의 시 합류 실패**. 계약 먼저.
- 이미지 모델 비용이 LangSmith에 0으로 보일 수 있음(토큰 비기반).
- 채팅 무상태 유지 시 멀티턴 슬롯/맥락 한계 → C 항목에서 결정.
