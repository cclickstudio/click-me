## 1. 단위 단가 (B_unit — generate 1콜, 실측)

| 모델 | low | medium | high | 실측 비고 |
| --- | --- | --- | --- | --- |
| **gpt-image-1** | $0.011 | $0.042 | $0.167 | 3/3 성공, 지연 13~19초 |
| **gpt-image-2** | $0.006 | $0.053 | $0.211 | 3/3 성공, 지연 16~20초 |
| **gemini-2.5-flash-image** | — | $0.040 | — | 실측 **~1,322 토큰**/장, 지연 7~9초 |
| **gemini-3-pro-image** | — | $0.044~0.048† | — | 실측 **~1,500 토큰**/장, 지연 17~20초 |

† **gemini-3-pro 금액은 잠정** — 토큰 수(~1,500)는 실측이지만, 우리 계산은 flash 단가($30/1M)를 적용한 값이야. pro의 이미지 출력 토큰 단가가 더 높을 가능성(공개가 $120/1M 설이 맞으면 장당 ~$0.18)이 있어 **Google 콘솔 확인 전까지 확정 아님**. 반면 gemini-2.5는 1,322토큰×$30/1M=$0.040으로 공개가와 일치해 신뢰 가능.

> gpt-image의 low/med/high 값은 OpenAI 공시가와 정확히 일치(우리 단가표 기반). 이번 측정은 "각 티어가 실제로 동작하고 그 가격표가 맞는지"를 검증한 것 — edit 계열의 입력 이미지 토큰 가산분은 이 정액에 안 잡히니 실제 청구는 OpenAI 콘솔에서 확정.

## 2. 실제 파이프라인 (A_pipeline — openai 누끼+인페인팅)

| op | gpt-image-1 low/med/high | gpt-image-2 |
| --- | --- | --- |
| remove_background(누끼) | $0.011 / $0.042 / $0.167 (3/3) | **불가** |
| edit_with_mask(인페인팅) | $0.011 / $0.042 / $0.167 (3/3) | 측정 스킵 |

**gpt-image-2는 누끼(배경제거) 불가** — API가 `Transparent background is not supported for this model.`(400)로 거부. 즉 gpt-image-2는 generate 단독으론 쓸 수 있어도 **현재의 누끼+인페인팅 상품보존 파이프라인엔 그대로 못 넣음**(누끼 대안 필요).

## 3. LangSmith 대조 — 이미지 비용은 안 잡힌다(실증)

`export_cost_matrix.py`로 42개 성공 run을 대조한 결과, **LangSmith가 자체 계산한 이미지 비용(LS비용$)·토큰은 거의 전부 공란/0**이었어(gemini-2.5만 부분적으로 $0.0032). 결론:

- LangSmith 총비용은 이미지 모델 실비를 반영하지 못한다 → 기존 트러블슈팅 문서의 **"생성 1회 약 $0.02"는 텍스트 토큰만 잡힌 값**이고 이미지 실비(회당 medium ~$0.17)가 누락돼 있었음.
- 이제 `core.tracing.record_image_cost`가 run 메타데이터에 `cost_usd·image_model·image_quality·operation`을 남기므로, **LangSmith UI에서 모델×품질×op별로 필터·분해 가능**(이번 작업의 핵심 산출).
- 최종 확정 청구액은 **OpenAI/Google 콘솔**이 정답지(같은 시간대 대조).

- **현재 기본(gpt-image-1 medium)**: 회당 시안 3장 **약 ₩270 / $0.18**, 시안 1장 완전원가 **약 ₩90 / $0.06**. 비용의 대부분은 이미지 API.

- **gpt-image-2**는 generate는 low가 더 싸지만($0.006) high는 더 비싸고($0.211), **누끼 미지원**이라 상품보존 파이프라인 교체엔 부적합.
- **gemini 계열**은 flash가 장당 $0.040으로 openai medium과 동급·최저가군. pro는 품질↑지만 단가 미확정(콘솔 확인 필요).
