# 채팅 오케스트레이션 → `deepagents` 클린 재작성 계획 (정책=프롬프트, LLM 판단)

## Context — 왜 이 작업을 하나

현재 채팅은 **2-레이어**다. ① `domain/chat/orchestrator.py`(1074줄)가 `classify→route` + 키워드·정규식 fast-path로 직접 라우팅하는 1차 라우터, ② `api/assistant/deep_agent.py`(829줄)는 "deep" 인텐트일 때만 도는 손수 짠 plan→act→dispatch 루프. 둘 다 LangGraph 저수준 API로 직접 구현돼 유지보수 부담이 크다.

**결정(확정):**
1. `deepagents.create_deep_agent` 하나를 통합 채팅 엔트리포인트로 만들어 2-레이어를 모두 대체한다.
2. **표면 유지(호환 어댑터) 없이 `chat.py`·인터페이스를 클린 재작성**한다.
3. **실시간 스트리밍을 처음부터** 도입한다(프론트 포함).
4. **키워드·정규식으로 판단하던 룰을 전부 제거하고, 라우팅·액션 선택 정책을 시스템 프롬프트에 인코딩해 LLM이 자연어를 직접 판단**하게 한다. 결정형 동작(위젯 폼·DB 호출)은 LLM이 호출하는 **tool**이 수행한다(판단은 LLM, 실행은 tool).

권한은 전부 사용자에게 있으므로 공용부(`core/`·`api/main.py`·`chat.py`·의존성)를 자유롭게 수정한다. 동인 — 유지보수성·에이전트 역량·스트리밍/관측성·표준화.

**트레이드오프(수용됨)** — 즉시 처리되던 명령("시뮬 돌려줘")도 이제 LLM 라우팅 1회(지연·토큰) 비용이 들고 드물게 오라우팅 가능. 완화: 명확한 정책 프롬프트 + 라우팅 temperature 0 + 구조화 tool-calling + 라우팅 eval. **이득** — 패러프레이즈·오타·복합 의도까지 유연, 정규식·pre-router·미들웨어 통째 제거로 코드 대폭 감소, deepagents 본래 방식(프롬프트 정책+tool)과 일치.

## 핵심 설계 원칙

1. **정책 기반 LLM 판단.** 기존 키워드·정규식 룰(`_SIM_RUN_RE`/`_GEN_RUN_RE`·`/비교`·템플릿 키워드·`_is_report`·`_is_batch_sim`·브랜드 cue 등)을 **전부 제거**한다. 라우팅·액션 정책을 **시스템 프롬프트**(`prompts.py`)에 선언하고, LLM이 자연어를 판단해 알맞은 **tool**을 호출하거나 서브에이전트에 위임한다. tool이 위젯 meta·DB 동작을 실행한다.
2. **클린 재작성(표면 유지 없음).** `build_chat_orchestrator`/`ChatTurn`/`ChatAnswer` 어댑터를 만들지 않는다. `chat.py`가 통합 agent를 직접 `astream`해 SSE를 바로 뽑는다. 가짜 청크(`_chunks`)·`deep_agent.py`·구 그래프는 만들지 않고 제거한다.
3. **안전망 = 골든 + 라우팅 eval.** "tool→위젯" 실행은 순수 골든 테스트로, "자연어→어느 tool" 판단은 대표 문구 eval(실/모의 LLM)로 검증. 레거시는 git 히스토리에 남긴다.
4. **신규 `.py`는 첫 줄 한국어 헤더 주석**(CLAUDE.md ⑥). 커밋은 시맨틱 단위 분리.

> **구조화 신호 예외** — `[생성결과]` 접두사는 사용자 자연어가 아니라 프론트가 보내는 **결과 콜백(프로토콜 신호)**이다. LLM 판단 대상이 아니므로 얇은 구조화 입력 핸들러로 유지한다(원하면 이것도 LLM 판단으로 전환 가능). 메모리 recall(의미검색)·brand 컨텍스트 주입도 "키워드 판단"이 아니라 RAG 컨텍스트라 그대로 둔다.

## 검증된 사실 / 선행 조건

- **deepagents 0.6.12**(Python ≥3.11) `requires-dist`: `langchain>=1.3.11`, `langchain-core>=1.4.8`, `langchain-anthropic>=1.4.7`, `langchain-google-genai>=4.2.5`. 현재 lock langchain **1.3.4**·langchain-anthropic **1.4.4** → **마이너 범프+락 갱신+스모크**.
- **`create_deep_agent(model, tools, *, system_prompt, middleware, subagents, ..., checkpointer, store, ...) -> CompiledStateGraph`**. LangChain `create_agent` 위. 위임은 `task()` 툴. `checkpointer=`/`store=` 직접 파라미터.
- **답변 LLM = `domain/chat/llm.py::build_chat_llm` → 기본 `anthropic`/`claude-sonnet-4-6`**(라우팅 판단에 충분한 체급). 분류·슬롯은 현재 `gpt-4o-mini`.
- **`SqlMemoryStore`는 `BaseStore` 비상속** → `store=` 직접 주입 불가. 메모리는 `ManagementMemory` `@tool`+`chat.py` 주입.
- **채팅 프론트는 `sse.ts` 미사용** — `ChatConversation.tsx::consumeStream`이 `fetch`+reader로 직접 소비 → `sse.ts` 무수정.
- **기존 채팅 테스트 전무** → 골든/eval 선작성.

## 1. 타깃 모듈 구조 + 신규 요청 흐름

합성은 **api 계층**(`domain → api` 역의존 금지).

```
api/assistant/
├── deep_agent_builder.py  [신규] build_unified_chat_agent(settings) = create_deep_agent(
│                                  system_prompt=정책, tools=[액션툴…], subagents=…, checkpointer=…).
│                                  deepagents 부재/충돌 시 create_agent 폴백.
├── prompts.py             [신규] 라우팅·액션 정책 시스템 프롬프트(어떤 의도→어떤 tool/위임).
├── chat_state.py          [신규] UnifiedChatState(widget/sub_meta/loop 등 필드).
├── subagent_tools.py      [신규] 액션 tool 전부 + 서브에이전트 위임 tool + remember/recall.
└── wiring.py              [개편] build_unified_chat_agent 일원화.

domain/chat/
├── widgets.py             [신규] 위젯 meta 순수 함수(tool들이 사용).
├── helpers.py             [신규] 순수 헬퍼(_format_ltm/_format_brand/_format_clio_kb) — 컨텍스트 주입용.
├── result_callback.py     [신규] `[생성결과]` 구조화 콜백 + 개선루프(loop_state) 처리.
├── orchestrator.py        [삭제] _Intent/_State/노드/정규식 fast-path 전부 폐기.
└── loop_state.py/history.py/llm.py/retriever.py  [유지]

api/routers/chat.py        [재작성] 통합 agent 직접 astream → SSE. _chunks·classify·short-circuit 폐기.
api/assistant/deep_agent.py [삭제]
```

**신규 요청 흐름** — 사용자 입력 → `chat.py`가 (구조화 콜백 `[생성결과]`면 `result_callback`로) 아니면 통합 `agent.astream` → ① LLM이 **system_prompt 정책으로 의도 판단** → 알맞은 **tool 호출**(위젯/단축동작) 또는 `task()` **서브에이전트 위임** → ② tool이 위젯 meta·DB 동작 실행 → 토큰·진행 이벤트를 **실시간 SSE**로 → 위젯/카드 meta는 끝에 한 번.

## 2. 기능 재배치 — 정책(프롬프트)으로 판단, tool로 실행

키워드/정규식 트리거는 **삭제**. 대신 각 동작을 **tool**로 만들고, 시스템 프롬프트의 정책이 "어떤 자연어 의도면 어떤 tool"을 LLM에게 지시한다.

| 기능 (기존 트리거) | 신규 tool (LLM이 정책으로 판단해 호출) | 위젯/출력 |
|---|---|---|
| 시뮬 실행 (`_SIM_RUN_RE`) | `run_simulation` | `sim_form` (Command(update={widget}, goto=END)) |
| 시안 생성 (`_GEN_RUN_RE`) | `run_generation` | `gen_form` |
| 비교 (`/비교`) | `compare_simulations` | `sim_list`(compare) |
| 리포트 (`_is_report`) | `generate_report` | `report_ready` |
| 템플릿 목록/불러오기/저장 (키워드) | `show_templates`/`load_template`/`save_template` | 텍스트/`sim_form`·`gen_form` 프리필 |
| 배치 (`_is_batch_sim`) | `batch_simulation` | `batch_sim_form` |
| 브랜드 조회/추출 (cue 키워드) | `show_brand`/`extract_brand` | 텍스트 / side-effect upsert |
| 캠페인 생성·관리 | `create_campaign`/`manage_campaign` | `create_campaign`/`campaign_action` |
| 성과·운영 질문 | `ask_management` 위임 | 카드(RESULT/REVIEW/ACTIONBAR) |
| 시뮬/생성 결과 해석 | `ask_simulation`/`ask_generator` 위임 | 텍스트+citations |
| classify(`_Intent`) | **삭제** → system_prompt+subagent description이 라우팅 | — |
| advise(CLIO KB) | 메인 모델 직접 답(+CLIO KB tool/preamble) | 텍스트 |
| deep(멀티도메인) | 메인 모델 + 복수 `task()` 위임 | 합성 |
| 생성결과 콜백 (`[생성결과]`) | **LLM 아님** — `result_callback` 구조화 핸들러 + loop_state | `approval`/loop_done |

메모리 recall·brand 컨텍스트는 의미검색/RAG라 라우팅 판단과 무관 — 진입부에서 system_prompt/state로 주입(키워드 룰 아님).

## 3. 서브에이전트 와이어링 — `@tool` 어댑터 (CompiledSubAgent 아님)

**충실도 > 네이티브성.** 현 핸들러는 어댑터 작업을 한다 — management `thread_id=f"mgmt-{session_id}"` 고정·`memory_context` 주입·`AskRequest` 셰이핑·`suggested_action`/`citations`→meta. `CompiledSubAgent`는 `messages` 키만 주고받아 이 로직이 유실되고 카드·HITL 재개가 깨진다. → `ask_management`/`ask_simulation`/`ask_generator`를 얇은 `@tool`로, 텍스트는 ToolMessage·**meta는 `Command(update={"sub_meta":...})`로 state 누적**. 실시간 진행은 `get_stream_writer()`. 액션 tool은 `Command(update={"widget":...}, goto=END)`.

## 5. 실시간 스트리밍 (처음부터)

**SSE kind:** 기존(`progress`/`meta`/`approval`/`done`) + `plan`·`step`/`tool`·`subagent`. **`text`는 실제 LLM 토큰**(24자 fake chunk 폐기). 위젯-only 응답은 토큰 없이 `meta`+짧은 안내.

```python
if is_result_callback(req): return await result_callback.handle(req)   # [생성결과] 구조화 경로
async for ns, mode, chunk in agent.astream(
        {...}, config, stream_mode=["messages","custom","updates"], subgraphs=True):
    if mode=="messages":   # AIMessageChunk → _sse("text", token=...)
    elif mode=="custom":   # _sse(chunk["kind"], **chunk["payload"])  # step/subagent/plan
    elif mode=="updates":  # acc_meta 누적(widget/sub_meta/source)
yield _sse("meta", meta=acc_meta); ... approval/persist/remember/done ...
```
`subgraphs=True`라야 서브에이전트 토큰이 부모로 올라온다. **프론트** `consumeStream`에 새 kind 핸들 추가(`plan`/`step`/`subagent`). `text`·위젯 11종 분기·`meta.widget`·`sse.ts` 무수정.

## 6. 단계별 실행 순서

- **Phase 0 — 의존성·스파이크·안전망.** `uv add deepagents` 충돌 확인(충돌 시 `create_agent` 폴백 확정), 현 동작을 골든+라우팅 eval로 박제(§8). 의존성 범프+락+스모크.
- **Phase 1 — 신규 통합 에이전트 코어.** `prompts.py`(정책)·`subagent_tools.py`(액션 tool 전부+위임 tool)·`deep_agent_builder.py`·`chat_state.py`, `domain/chat/widgets.py`·`helpers.py`·`result_callback.py`. `ainvoke` 기준 골든/eval 통과.
- **Phase 2 — `chat.py` 실시간 스트리밍 재작성 + 프론트.** `astream(...subgraphs=True)`→SSE(새 kind), `[생성결과]`는 `result_callback`로 분기, `/approve`·`/loop-state` 연결(loop_state 유지). 프론트 `consumeStream` 새 kind.
- **Phase 3 — 레거시 제거 + 검증.** `deep_agent.py`·`orchestrator.py`·`build_chat_deep_runner` 삭제. 골든/eval green, Claude Preview 화면 증거, LangSmith 신/구 비교(라우팅 정확도·도구호출·지연·비용).

## 7. 리스크 & 오픈 퀘스천

1. **LLM 라우팅 정확도·비용·지연**(트레이드오프 수용). 완화: 정책 프롬프트 명확화(의도→tool 예시·우선순위)·temperature 0·structured tool-calling·라우팅 eval로 회귀 감시·LangSmith로 턴당 라우팅 정확도/비용 모니터. 명백 명령의 추가 지연은 실시간 스트리밍의 즉각 피드백으로 체감 완화.
2. **deepagents 무거운 하네스.** `skills=[]`·general-purpose 서브에이전트 비활성·`subagents`=우리 3개·FS backend 미사용·최소 prompt. slim/HarnessProfile 사용.
3. **deepagents ↔ langchain 호환.** Phase 0 스파이크. 충돌 시 `create_agent`+미들웨어 직접 조립 폴백 내장.
4. **개선루프 HITL은 `interrupt_on` 아님** — 인메모리 `loop_state`+`/approve`+프론트 ApprovalWidget 유지. management 서브에이전트 내부 HITL은 자체 thread `mgmt-{session}`로 `@tool` 어댑터에서 보존.
5. **thread_id 누적 dedup** — thread=session_id 누적 + 프론트 풀히스토리 재전송 → `add_messages` 중복 가능. orchestrator.py:1033–1041 "체크포인트 비었을 때만 시드" 로직 이식.
6. **meta 순서/`source` 게이트** — 위젯-only 응답 즉시 `meta`+짧은 text. 신호 tool 결과 `source` 고정(현 `_state_to_result` 정책 이식)으로 프론트 배지/카드 오발동 방지.
7. **오픈** — `/비교` 등 슬래시 명령을 LLM 판단으로 통일할지, 명시 단축키로 별도 유지할지(현재 정책상 LLM 판단으로 통일 가정).

## 8. 검증

`backend/tests/chat/`(신규)+`conftest.py`.
- **8a tool 실행 골든(순수, LLM 무관):** 각 액션 tool 호출 시 `meta.widget.type`·prefill·`source`·`Command(goto=END)` 정확. 11종 위젯·캠페인 신호 전수. `result_callback`의 개선루프 1·2·3턴 approval / MAX_LOOP loop_done·`/approve` 카운트·차단.
- **8b 라우팅 eval(LLM in-the-loop):** 대표 자연어 문구 세트("시뮬 돌려줘"/"이 광고 시뮬 한번 해봐"/"두 버전 비교"/"성과 어때?"/"개선 시안까지") → 기대 tool/위임 매칭률. 실 LLM(저비용) 또는 tool-choice 모의. 패러프레이즈·오타 포함. 임계치 회귀 감시.
- **8c CI/화면:** `cd backend && uv run ruff format . && uv run ruff check . --fix`(CLAUDE.md ①) → `uv run pytest tests/chat -v`. Claude Preview로 실 채팅(위젯·토큰 스트림) 스크린샷·네트워크 증거(CLAUDE.md ⑤).
